# 🐦 คู่มือการพัฒนาสถาปัตยกรรม Edge AI สำหรับจำแนกเสียงนกบน ESP32 (TinyML)

เอกสารฉบับนี้อธิบายถึงขั้นตอน โครงสร้างไฟล์ และสถาปัตยกรรมของโปรเจกต์การนำโมเดลปัญญาประดิษฐ์ (1D-CNN) ที่ฝึกสอนด้วย Google Colab มาติดตั้งและรันบนไมโครคอนโทรลเลอร์ ESP32 (Edge Computing) ผ่านเฟรมเวิร์ก TensorFlow Lite for Microcontrollers (Native)

---

## 🚀 1. ภาพรวมการทำงาน (Workflow)

กระบวนการทำงานแบ่งออกเป็น 2 ส่วนหลัก:

1. **ฝั่งเซิร์ฟเวอร์ (Google Colab):** ใช้สำหรับประมวลผลข้อมูลเสียงดิบ สกัดฟีเจอร์ (MFCC) สร้างโมเดล 1D-CNN ฝึกสอน (Train) และแปลงโมเดลให้อยู่ในรูปแบบ C++ Array (`.h`)
2. **ฝั่งฮาร์ดแวร์ (Arduino IDE / ESP32):** นำไฟล์ C++ Array ที่ได้มาคอมไพล์ร่วมกับไลบรารี TensorFlow Lite เพื่อรันการทำนายผล (Inference) บนบอร์ดโดยตรง

---

## 📂 2. คำอธิบายไฟล์ในโปรเจกต์

### 2.1 ฝั่ง Google Colab

ในฝั่ง Colab จะประกอบไปด้วยชุดคำสั่ง Python ที่ทำหน้าที่หลักๆ ดังนี้:

* **Audio Preprocessing:** โหลดไฟล์เสียงนก ตัดความยาวให้เหลือ 1.5 วินาที (Sampling Rate 16kHz)
* **MFCC Extraction:** สกัดจุดเด่นของเสียงให้อยู่ในรูปของ Mel-Frequency Cepstral Coefficients (MFCC) ขนาดมิติ `(200, 13)`
* **Model Training:** สร้างและเทรนโมเดล 1D-CNN ให้จดจำแพทเทิร์นเสียงนก 5 สายพันธุ์
* **TFLite Conversion:** แปลงโมเดล Keras เป็นไฟล์ `.tflite` แบบ Float32 (ไม่ทำ Quantization เพื่อหลีกเลี่ยง Error: Hybrid models not supported บน ESP32)
* **C++ Array Exporting:** ใช้คำสั่ง `xxd` แปลงไฟล์ `.tflite` และไฟล์ชุดข้อมูลทดสอบ (Test Set) ให้อยู่ในรูปแบบ C++ Header เพื่อนำไปใส่ใน Arduino IDE

### 2.2 ฝั่ง Arduino IDE (ESP32)

โปรเจกต์จะประกอบด้วยไฟล์ทั้งหมด 4 ไฟล์ ทำงานร่วมกันดังนี้:

#### 📜 `bird_inference_esp32.ino` (ไฟล์หลัก)

เป็นสมองสั่งการหลักของระบบ มีหน้าที่:

* โหลดไลบรารี `TensorFlowLite_ESP32` (Native)
* จองพื้นที่หน่วยความจำ SRAM (Tensor Arena) ขนาด 90KB สำหรับให้โมเดลใช้คำนวณ
* สร้าง `MicroInterpreter` เพื่อเชื่อมโยงโมเดลเข้ากับชุดคำสั่งคณิตศาสตร์ (`AllOpsResolver`)
* ดึงข้อมูล MFCC จากไฟล์ทดสอบ ป้อนเข้าสู่ `input_tensor` โดยตรง (Direct Feed)
* สั่งประมวลผล (Invoke) และดึงค่าความน่าจะเป็นจาก `output_tensor` มาเปรียบเทียบกับเฉลย (Ground Truth)

#### 📜 `bird_edge_1d_cnn.h` (ไฟล์สถาปัตยกรรมและค่าน้ำหนัก)

ไฟล์ที่ได้จากการแปลงโมเดล `.tflite` ด้วยคำสั่ง `xxd`

* ภายในบรรจุอาร์เรย์ฐานสิบหก (Hex Array) ตัวแปรชื่อ `bird_edge_1d_cnn_tflite`
* เปรียบเสมือน "ความจำระยะยาว" ของ AI ที่เก็บค่าน้ำหนัก (Weights) และโครงสร้างเลเยอร์ทั้งหมดเอาไว้ โดยประกาศใช้ `PROGMEM` เพื่อบังคับให้เซฟลง Flash Memory ป้องกัน RAM เต็ม

#### 📜 `esp32_mfcc_samples.h` (ไฟล์ชุดข้อมูลทดสอบ)

ทำหน้าที่เก็บข้อมูลทดสอบเพื่อใช้ยืนยันความแม่นยำ (Validation) บนฮาร์ดแวร์จริง:

* เก็บอาร์เรย์ของค่า MFCC ของจริงที่สกัดมาจาก Colab (ขนาด 2600 ตัวแปรต่อไฟล์) จำนวน 10 ไฟล์ (นกที่รู้จัก 5 ไฟล์ และ เสียงแปลกปลอม 5 ไฟล์)
* การป้อน MFCC ของจริงเข้าบอร์ดโดยตรง ช่วยแก้ปัญหาที่โมเดลตอบ 20% ทุกคลาสอันเกิดจากการใช้คลื่นเสียงจำลองที่บอร์ดสร้างขึ้นเอง

#### 📜 `audio_processor.h` (ไฟล์จัดการท่อส่งข้อมูล - Pipeline)

* โครงสร้างเดิมเตรียมไว้สำหรับสกัดฟีเจอร์บนบอร์ด (On-board DSP)
* *หมายเหตุ: ในเวอร์ชันปัจจุบันเราบายพาส (Bypass) ฟังก์ชันในไฟล์นี้ และใช้วิธีโหลด MFCC สำเร็จรูปป้อนเข้า Tensor โดยตรงเพื่อลดภาระการคำนวณของบอร์ดและคงความแม่นยำให้เทียบเท่า Colab*

## ⚙️ 3. การตั้งค่าสภาพแวดล้อม (Environment Setup)

เพื่อให้คอมไพล์ผ่านโดยไม่เกิด Error หน่วยความจำล้น หรือ Error จากการขัดแย้งของฮาร์ดแวร์ ต้องตั้งค่า Arduino IDE ดังนี้:

1. **ESP32 Board Version:** ต้องดาวน์เกรดเป็นเวอร์ชัน `2.0.17` (เพื่อเลี่ยง Error `PERIPH_I2S0_MODULE` ในเวอร์ชัน 3.x.x)
2. **Board:** เลือก `ESP32 Dev Module`
3. **Partition Scheme:** เลือก `Huge APP (3MB No OTA/1MB SPIFFS)` เพื่อรวมพื้นที่ Flash Memory ให้ใหญ่พอที่จะบรรจุโมเดลและไฟล์ทดสอบ

## 🧠 4. การวิเคราะห์ผลลัพธ์และพฤติกรรมของโมเดล (Model Analysis)

ในการทดสอบระบบด้วยไฟล์เสียงจำนวน 10 ไฟล์ (เป็นนก 5 สายพันธุ์ที่โมเดลรู้จัก และเสียงแปลกปลอม/เสียงนกชนิดอื่นที่โมเดลไม่เคยได้ยินมาก่อนอีก 5 ไฟล์) พบปรากฏการณ์ **Softmax Overconfidence** ซึ่งเป็นข้อจำกัดทางสถาปัตยกรรมของโมเดล AI ประเภทจำแนกหมวดหมู่ปิด (Closed-set Classification)

### 🔴 ปัญหาที่พบเมื่อเจอ "ข้อมูลที่ไม่รู้จัก (Unknown)"

เมื่อระบบเผชิญหน้ากับเสียงที่ไม่เคยเห็นมาก่อน AI มักจะทำนายผลลัพธ์ผิดพลาดด้วยค่าความมั่นใจ (Confidence Score) ที่สูงทะลุ 90%+

**การวิเคราะห์สาเหตุเชิงลึก:**

> เลเยอร์สุดท้ายของโมเดลคุณคือฟังก์ชัน **Softmax** ซึ่งมีกฎเหล็กว่า *"ผลรวมความน่าจะเป็นของทุกคลาสต้องเท่ากับ 100% เสมอ"*
> **สิ่งที่เกิดขึ้น:** โมเดลของคุณถูกสอนให้รู้จักโลกที่มีนกแค่ 5 ชนิด มันไม่เคยรู้จักเสียงลม เสียงหมาเห่า หรือเสียงรถยนต์ เมื่อเราส่งเสียงแปลกปลอมเข้าไป โมเดลจะพยายามบังคับ (Force) นำฟีเจอร์แปลกๆ นั้นไปจับคู่กับนก 5 ชนิดนี้ให้ได้ และมักจะไปตกที่คลาสใดคลาสหนึ่งด้วยคะแนน 90%++ ทำให้การใช้ `if (confidence < 0.60)` แบบที่เราเขียนไว้ในโค้ด ดักจับไม่ได้ผล

### 💡 แนวทางการแก้ไขในอนาคต (Future Improvements)

เพื่อแก้ปัญหานี้และอัปเกรด AI ให้พร้อมใช้งานจริงในระดับโปรดักชัน (Production-ready) ต้องปรับแก้ที่ขั้นตอนการเทรนข้อมูล (Colab) ดังนี้:

1. **เพิ่มคลาสที่ 6 (Background Noise / Unknown):** รวบรวมข้อมูลเสียงป่า เสียงลม หรือเสียงรบกวนทั่วไป นำมาเทรนเป็นคลาสเพิ่มเติม เพื่อให้โมเดลมีทางออกเมื่อเจอข้อมูลที่ไม่ตรงกับนกเป้าหมาย
2. **Data Augmentation:** เพิ่มความทนทาน (Robustness) ให้โมเดลด้วยการปรับ Pitch หรือใส่ White Noise ลงไปในชุดข้อมูล Training Set เพื่อลดอาการ Class Imbalance และเพิ่มความแม่นยำโดยรวม
